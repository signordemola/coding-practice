# Interview bank

Real topics that platform interviews and tests ask about, each mapped to a module in `SYLLABUS.md`.
**This folder is a question source, not a second syllabus.** Every topic here points to a module that already exists in `SYLLABUS.md`. The syllabus is frozen: if a question needs something missing, it's practised inside current work, never added as a module. Questions that point to "pull in only when needed" modules wait until a real task needs them.

| File | Platform | What it gives |
|---|---|---|
| `micro1.md` | micro1 | Interview topics from 7 practice roles closest to my work |
| `turing.md` | Turing | Test format and quick-check topics for stack tests and live coding |
| `study-guide.md` | All roles | My reference notes, one file for every role, organised by topic, with a role map and an interview log. Tutors quiz me from it; they never read the answers to me. |

## How Codex uses it
- **Speak step (every session):** one question matching today's module. Score 0–7 with the rubric in `AGENTS.md`. Log it in `PROGRESS.md` → Interview bank. Under 5 goes to the review queue.
- **Quick check (start of every review):** 5 multiple-choice questions on precise details of the current track, written by Codex in the style of `turing.md`. Log the score.
- **Timed drill (weekly, M8):** one problem, 25–45 minutes, no hints during the timer. Afterwards, review it with the hint ladder.
- **Mock interview (every 2 weeks):** 6 questions from different files, no notes, about 1 minute each, then one timed problem.
- **Never hand me model answers.** Same hint ladder as code.
- **Interview within 7 days:** follow "Interview pull-ins" in `SYLLABUS.md`, then return to the Path.
